# Visual and behavior acceptance review

Review the actual consuming page. The goal is deliberate original composition inspired by a selected image, not a brand replica or a generic dashboard with changed palette.

## Static fidelity before motion

Capture selected original and rendered page at comparable widths. Compare heading width/scale, art-to-copy area, empty-space distribution and section/navigation silhouette. Inspect hero, then below-fold page. Equilibrium needs a rule canopy/editorial descent; meadow a narrow creation task; prism a blue-ribs-to-cream transition; landscape a real product artifact. A Theme value alone does not achieve a direction.

Measure approximate ratios rather than claiming exact CSS extraction. Fix composition before tiny border differences. Screenshot overlays are meaningful for a deliberately matched target; differing copy/viewport does not support a pixel-perfect claim. Record image IDs, borrowed composition, replaced assets and product-required deviations.

## Control and material review

Every interaction uses the appropriate library/host component and actual behavior. Check raised-button edge/press/release, stationary focused inputs, contrast, visible focus, selected/invalid/pending/disabled states and long labels. Check coherent lighting, depth order and no texture over text. Inspect objects at native scale. A MaterialObject or DeviceFrame cannot compensate for poor art/content inside it.

## Complete journey

Run task → validating/pending → useful result → edit/reverse → retry/cancel as applicable. Empty/error states retain context. Links resolve, dialogs close/restore focus, forms preserve data after failure and replay does not repeat writes. Repeated taps/fast changes must not leave stale pressed/selected state.

## Responsive and motion

Inspect desktop, 390×844 mobile and a smaller/shorter viewport. Check wrapping, header disclosure, reachable actions, readable artifacts and intentional art clipping. At 200% zoom no essential content disappears. Resizing is not proof of virtual keyboard behavior on a phone.

Test normal motion, paused ambient and OS reduced motion separately. First paint/disabled JavaScript should retain core content. Reveals must not hide focused content. Real success is visible without spectacle delay. Pause stops associated ambient work. Inspect paint/input cost when scale justifies it; do not infer device performance from source.

## Evidence wording

Record actual commands, paths, viewport observations and limits. Build/types establish code contracts. Packed-consumer checks establish distribution. Screenshots establish composition at exercised widths. Interaction walkthroughs establish the exercised flow. Production, device performance, source accuracy, license/payment or security guarantees require separate evidence.

Call gaps concrete: wrong title/art ratio, weak edge light, missing artifact, excessive card padding, dead CTA or unreadable phone preview. Use the selected direction's acceptance/exclusions as the final filter.
